# Agent Notes

Agent Note 只记录代码本身难以表达、且后续维护者仍需要理解的设计选择。Skill 描述“怎么重复做一类工作”；Agent Note 解释“为什么本项目选择了这条长期路线”。

## 状态和文件位置

每份记录放在一个状态目录中，文件名用首次提出日期和简短主题：

```text
.agents/notes/
  proposed/YYYY-MM-DD-topic.md
  implemented/YYYY-MM-DD-topic.md
  rejected/YYYY-MM-DD-topic.md
  archived/YYYY-MM-DD-topic.md
```

- `proposed/`：方案尚未完整落地；记录验收条件和风险。
- `implemented/`：决策已进入代码或流程；记录当前事实，并在实现变化时同步更新。
- `rejected/`：记录曾认真考虑但拒绝的方案，以及当时的证据和拒绝原因。
- `archived/`：只放已经实施且不再指导当前决策、但仍有历史价值的冻结记录；不要把归档记录当成当前权威。

移动状态时，改目录并按对应模板改写内容。提案不是实施授权，也不替代用户对本次改动的范围确认。

## 什么时候写

适合写：影响多个模块或未来任务的接口/状态决定；精简功能时放弃的兼容或恢复能力；有高风险替代方案的验证结论；值得防止重议的失败尝试。只有代码、测试和现有文档仍不能解释的长期理由才单独记录。

不适合写：常规实现步骤、短期任务清单、可从代码直接读出的事实、局部 UI 或机械改动的流水账。每次拟新增 Note 前先查找同主题记录，并对可能被取代的记录做局部审查；不要借此启动无关的全库清理。

## 模板

从 `templates/` 复制与当前状态匹配的文件。一个决定应留下问题、选择、被放弃的替代方案、影响和验证证据。已经实施的记录不得继续使用计划口吻。使用 `$agent-notes` 执行 Capture、Finalize、Retrieve 或 Maintain；若项目提供格式校验器，运行它确认生命周期和章节一致。
